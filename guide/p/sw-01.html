현장의 AI · 진로 연결

서비스 기획자(PM)는 사용자의 불편을 기능 명세로 바꾸고, 개발자·AI가 그 명세로 만들어요. 명세가 흐리면 결과도 흐려요 — 생성형 AI 시대에 더 중요해진 능력이에요.

3만들기 전에 먼저 공부하기

  1. 제미나이 캔버스 기본 — 도구 T1 · 생성·수정·공유 제미나이 Canvas 완벽 가이드 ↗
  2. 좋은 주문 vs 나쁜 주문 — “시험 기간 타이머 앱” vs “무엇이든 되는 앱” — 기능이 1개일수록 성공
  3. 생성 대기 시간 설계 — 생성 중 “프롬프트 해부도” 판넬로 설명하며 기다리게 해요
  4. 배포 — 캔버스 공유 링크 또는 GitHub Pages GitHub Pages (무료 웹 배포) ↗

한 줄 소개
방문자가 4칸 주문서로 앱을 주문하면 6대 요소 프롬프트로 바꿔 5분 안에 만들고, 버그 하나를 함께 고친 뒤 QR로 건네는 즉석 앱 공방
배운 내용을 어떻게 연결했나요?
바이브 코딩 입문의 6대 요소 프롬프트·버그 틀·6점 체크리스트로 부스 전체를 운영하고, 히어로 UI/UX·IPO 차시로 주문을 입력→처리→출력으로 쪼갭니다.
방문자가 바꿔 볼 수 있는 ‘AI의 원리’
방문자가 주문서의 구체성을 바꾸고 버그를 직접 말해 보며, 생성형 AI는 지시(명세)가 구체적일수록 의도에 맞게 만든다는 원리를 체험합니다.
맞이 (30초)
“지금 나에게 필요한 앱 하나를 주문해 보세요” 하고 4칸 주문서를 건넵니다.
체험 (3~4분)
주문서를 프롬프트로 바꿔 생성하는 과정을 지켜본 뒤, 완성된 앱을 직접 써 봅니다.
AI가 틀리는 순간 (1분)
찾은 버그를 버그 틀 문장으로 말해 고치고, 애매하게 말하면 엉뚱하게 고쳐지는 것을 봅니다.
정리·진로 카드 (1분)
완성 앱을 QR로 받고 서비스 기획자·QA 엔지니어 진로 카드를 받습니다.
Plan B
인터넷이 끊기면 미리 만든 완성본 5개 중 골라 고칠 점을 말하는 활동으로 운영합니다.
